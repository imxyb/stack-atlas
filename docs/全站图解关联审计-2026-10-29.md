## 正确性边界说明

- Next-Key Lock 图显示的 `(15,20]` 是**单个锁定区间示意**，不代表任何 SQL 的完整 InnoDB 锁集；实际锁取决于索引、扫描顺序、隔离级别与执行计划。
- MySQL 两阶段提交是 Redo Prepare → Binlog 写入 → Redo Commit 的**机制示意**；保证能否经得住掉电，还需检查 flush/sync 配置。
- Trie / Receipt / State Proof 图必须区分**数据被某区块头承诺**与**该区块头已获得最终性**。
- Solidity 的外部调用、重入、EIP-712、代理升级不能复用一张图代表所有攻击。
- KYT/AML 图中风险分与污染追踪属于分析模型，**不等于法律或事实上的确定归因**。

GitHub Actions 运行 `node scripts/validate-site.mjs`：
1. 确保所有图解的 ID 在运行时注册；
2. 逐题渲染 81 条绑定，检验模式切换；
3. 校验题图绑定表与 `audit-map.json` 一致；
4. 重复使用的图必须明确记录为 `intentionalReuse`；
5. 同时执行原有 Markdown、题库 ID、JavaScript、手机端和履历页检查。

`diagrams/engine.js` 负责通用图解渲染；各技术域文件放在 `diagrams/topics-*.js`，避免继续将几十个主题的逻辑堆在单一 HTML 中。
